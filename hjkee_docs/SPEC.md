## 📋 프로젝트 개요

행주기씨대종중의 기존 족보 시스템(으뜸족보, Uttom Internet Pedigree)과 문중 대표 사이트(hjkee.com)를 모던 스택으로 리뉴얼합니다.

### 핵심 미션

1. **데이터 보존**: 42,924명, 33세대, 800여 가문 혼인 네트워크의 100% 안전한 이전
2. **위원회 부담 절감**: 신규 등록 워크플로우 자동화로 행정 부담 80% 감소
3. **세대 격차 해소**: 31~33세대(현 청년층) 등록 급감 위기 대응 — 청년 친화 콘텐츠 레이어

### 데이터 규모

| 항목 | 수치 |
|------|------|
| 총 종친 | 42,924명 |
| 생존 종친 | 15,338명 (35.7%) |
| 사망 종친 | 27,586명 (64.3%) |
| 세대 범위 | 1세 ~ 33세 |
| 분파 구조 | 6개 대분파 → 7개 중분파 → 다수 세분파 (3단계 트리) |
| 양자관계 | 약 200건+ |
| 혼인관계 | 약 29,000건 (며느리 14,953 + 사위 14,210) |
| 통혼 가문 | 800여 본관 |

## 🏗️ 프로젝트 구조 (Monorepo)

```
hjkee/
├── apps/
│   ├── web/              # 메인 웹 (Next.js 15)
│   ├── admin/            # 위원회 관리자 대시보드
│   ├── mobile/           # Capacitor iOS/Android 앱
│   └── public/           # 문중 대표 사이트 (hjkee.com)
├── packages/
│   ├── ui/               # 공통 디자인 시스템 (shadcn/ui 기반)
│   ├── db/               # Supabase 타입 + 스키마
│   ├── domain/           # 도메인 로직 (촌수, 항렬자, 양자)
│   └── hanja/            # 한자 처리 (자동 추천, 폰트)
├── docs/                 # 본 문서 일체
├── scripts/              # 마이그레이션, 분석 스크립트
└── supabase/             # 마이그레이션, RLS, RPC 함수
```

**선택한 모노레포 도구**: Turborepo (대표님 빨리대리·해충방제 매칭 패턴 재사용)

## 💻 기술 스택

### 핵심
- **Next.js 15** (App Router, Server Actions, RSC)
- **TypeScript** (strict mode)
- **Supabase** (PostgreSQL 15 + Auth + Storage + Realtime + RLS)
- **Tailwind CSS** + **shadcn/ui**
- **Vercel** (배포 + Edge Functions)

### 도메인 특화
- **PostgreSQL ltree** — 분파 트리 계층 쿼리
- **PostgreSQL pg_trgm** — 한글/한자 부분 일치 검색
- **PostgreSQL tsvector** — 통합 풀텍스트 검색
- **PostGIS** — 묘소·주소 위치 (Phase 1.5)
- **PostgreSQL 재귀 CTE** — 직계 가계 / 촌수 계산

### 시각화
- **D3.js** — 가계도 인터랙티브 트리
- **Recharts** — 통계 대시보드 (인구 피라미드, 라인 차트)
- **react-d3-cloud** — 흔한 이름 워드 클라우드
- **자체 React 컴포넌트** — 모바일 카드 스택 가계도

### 모바일·앱
- **Capacitor 7** (iOS / Android)
- **FCM** (푸시 알림)
- **카카오맵 SDK** (지역 정보)

### 외부 통합
- **Gemini 2.5 Flash** — 본관 정규화, 옛 족보 OCR (대표님 무역 자동화 패턴 재사용)
- **iconv-lite** — EUC-KR → UTF-8 인코딩 변환

### ❌ 사용하지 않음 (의사결정 사항)
- **NICE 본인인증** — 위원회 수동 검증으로 대체
- **Toss Payments** — 농협 입금 + 매칭 코드로 대체

## 📅 개발 일정 (Phase 1 — 12주)

### Week 1: Kickoff
- 으뜸족보 DB 백업(.sql) 수령 및 분석
- 인코딩 변환 (EUC-KR → UTF-8)
- ERD 최종 확정
- Supabase 프로젝트 생성, 기본 스키마 배포
- 마이그레이션 스크립트 1차 작성

### Week 2: Migration
- 42,924명 인물 데이터 이전
- 양자관계 200건+ 정규화 (출계/입후 분리)
- 혼인관계 29,000건 + 본관 정규화 (Gemini Flash)
- 항렬자 자동 추출 (33세대 패턴 분석)
- 무결성 검증 보고서 (기존 통계와 100% 일치)

### Week 3: Search
- 인물 통합 검색 (한글·한자·자·호·관직·배우자)
- 동명이인 부친 검색 보조 UI
- 인물 상세 페이지 (개인자료, 사진, 족보 원문/번역)

### Week 4: Visualization (Desktop) ⭐ 마일스톤
- 5세대 인터랙티브 트리 (D3)
- 양자관계 점선 + 호박색 박스 표시
- 분파 단위 진입, 줌/드래그/검색 결합

### Week 5: Mobile + Responsive
- 카드 스택형 모바일 가계도 (스와이프)
- 어르신 친화 큰 글씨 + 한자 병기
- 전체 화면 반응형

### Week 6: Domain Logic
- 양자 출입현황 카드형 재구성
- 촌수 자동 계산 (LCA + 재귀 CTE)
- 생부/양부 라인 선택 옵션

### Week 7: Registration ⭐ 마일스톤
- 5단계 신규 등록 워크플로우
- 항렬자 자동 추천 + 한자 추천 엔진
- 사진 4매 자동 리사이즈
- 위원회 회원 인증 시스템 (가족관계 대조)

### Week 8: Admin Dashboard
- 신청 큐 관리 대시보드
- 통장 입금 자동 매칭 (코드 기반)
- 변경 이력 audit log
- 분파별 권한 분리 (RLS)

### Week 9: Statistics
- 9종 통계 메뉴 (인구 피라미드, Sankey, 워드 클라우드)
- 혼인 네트워크 시각화
- 카카오맵 지역 분포

### Week 10: Mobile App ⭐ 마일스톤
- Capacitor iOS/Android 빌드
- FCM 푸시 알림
- 가승보 PDF 생성 (한문 + 한글)
- TestFlight + Play 콘솔 내부 테스트

### Week 11: QA
- 전체 통합 테스트
- 어르신 5명 사용성 테스트
- 데이터 정합성 최종 검증

### Week 12: Launch ⭐ 마일스톤
- 프로덕션 배포 (Vercel + Supabase)
- 앱스토어 정식 심사 제출
- 위원회 교육 1회
- 1개월 무상 유지보수 시작

## ⚠️ 주의사항

### 절대 금지

1. **NICE 본인인증·Toss Payments 통합 시도 금지** — 명시적 제외 항목
2. **데이터 손실 가능성 있는 마이그레이션 — 반드시 백업 후 검증**
3. **사망자 정보 직접 수정 금지 — 위원회 검토·이사회 의결 필수**

### 반드시 준수

1. **모든 변경은 audit log에 기록** (person_change_log 테이블)
2. **한자 인코딩은 UTF-8 통일** — EUC-KR 데이터 손실 시 원본 보존
3. **분파별 RLS 권한 분리** — 다른 분파 종친 개인정보 노출 금지
4. **모바일 first** — 모든 화면은 모바일에서 먼저 검증

### 어르신 친화

1. **큰 글씨 (최소 16px 본문)**
2. **한자 병기** (한글 옆에 작은 한자)
3. **명료한 메뉴 이름** — 영어·외래어 최소화
4. **단순한 IA** — 3단계 깊이 이내
