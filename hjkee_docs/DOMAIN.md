## 1. 양자관계 (Adoption)

### 정의

**양자(養子)**: 법적 아버지와 친아버지가 다른 사람.

전통 한국에서 다음 상황에 양자를 들였습니다:
1. 아들이 없는 집안 (가장 흔함)
2. 장남이 일찍 죽어 손자 잇기
3. 종손(宗孫)이 끊김 — 종가의 대를 잇기 위해 가까운 일가에서 데려옴

**입후(立後)**: 양자 들이는 의식. 조선시대엔 예조에 신고까지 했습니다.

### 핵심 용어

| 용어 | 한자 | 의미 |
|------|------|------|
| 친부 | 生父 | 친아버지 |
| 친모 | 生母 | 친어머니 |
| 양부/계부 | 養父/系父 | 양아버지 (가계도상 진짜 부친) |
| 양모/계모 | 養母/系母 | 양어머니 |
| 출계 | 出系 | 다른 가문으로 양자 보냄 |
| 입후 | 入後 | 양자로 받음 |
| 계자 | 系子 | 양자 |
| 생자 | 生子 | 친아들 |
| 봉사손 | 奉祀孫 | 제사 잇는 손자 |

### 데이터 구조 함의

**일반 SW의 가정**:
```
자녀 → 부모는 1:1 또는 1:2 (친부·친모)
```

**한국 족보의 실제**:
```
자녀 → 친부·친모 (생물학적)
     → 양부·양모 (사회적·법적)  ← 가계도상 진짜 부모
```

즉 **한 사람이 4명의 부모**를 가질 수 있습니다.

### 시각화 규칙 (행주기씨대종중 합의)

```
실선 (━━): 가계 계승선 (양부·양모 라인)
점선 (┄┄): 생물학적 관계 (친부·친모 라인, 양자만 표시)
호박색 박스 (#fef3c7): 양자 또는 출계자
```

### 관계 타입 enum

```typescript
type RelationType =
  | 'biological_father'    // 친부 (生父)
  | 'biological_mother'    // 친모 (生母)
  | 'adoptive_father'      // 양부 (養父 / 系父)
  | 'adoptive_mother'      // 양모
  | 'out_adoption'         // 출계 (다른 가문으로 보냄)
  | 'in_adoption'          // 입후 (양자로 받음)
  | 'spouse'               // 배우자
  | 'child';               // 자녀 (역방향 캐시)
```

### 검색·표시 규칙

- **양자 출입현황 화면**: 두 줄로 표시 (출계 라인 + 입후 라인)
- **인물 상세 페이지**: 양부·생부 모두 클릭 가능
- **촌수 계산**: 사용자가 라인 선택 (생부 vs 양부)

## 2. 촌수(寸數)

### 정의

**촌수 = 두 사람 사이의 가족 거리** (서양 가계도엔 없는 한국 특화 개념).

### 계산 규칙

```
나 ↔ 부모     = 1촌
나 ↔ 형제     = 2촌
나 ↔ 조부모   = 2촌
나 ↔ 삼촌     = 3촌
나 ↔ 사촌     = 4촌
나 ↔ 5촌(당숙) = 5촌
...
나 ↔ 12촌    = 12촌 (사실상 매우 먼 친척)

행주기씨대종중 시스템: 직계 12대 + 방계 12촌까지 계산
```

### 알고리즘 (LCA)

```
촌수 = 두 사람의 최근접 공통조상까지의 거리 합

예: A와 사촌형 B
1. A의 조상: 부친 → 조부
2. B의 조상: 부친 → 조부 (같은 조부!)
3. 공통조상 = 조부
4. A→조부 거리 = 2, B→조부 거리 = 2
5. 촌수 = 2 + 2 = 4촌
```

이건 **그래프의 LCA (Lowest Common Ancestor)** 표준 문제입니다.

### 양자관계 변수

같은 두 사람 사이에도 **친혈통 촌수**와 **가계도 촌수**가 다를 수 있습니다.

```sql
-- DB 함수: calculate_chonsu(person_a, person_b, use_adoptive BOOLEAN)
-- use_adoptive = TRUE  → 양부 라인 (가계도 기준)
-- use_adoptive = FALSE → 친부 라인 (친혈통 기준)
```

UI에서 사용자에게 라디오 버튼으로 선택받아야 함.

## 3. 항렬자(行列字)

### 정의

**항렬자**: 같은 세대 종친의 이름에 공통으로 들어가는 한자.

가문에서 미리 정해놓은 표를 기반으로, 자녀 이름을 지을 때 의무적으로 사용합니다.

### 위치 규칙 (교대 패턴)

한 세대 건너 항렬자 위치가 바뀝니다:

```
세대 N:    [항렬자][이름자]    예: 老俊, 宇根, 世煥, 東衍, 浩成
세대 N+1:  [이름자][항렬자]    예: 成度, 永舒, 光舒, 鳳衍

→ "앞·뒤 교대 항렬"
```

### 행주기씨 항렬자 (자체 추출 + 위원회 검수 필요)

이름 빈도 데이터로부터 추출 가능한 패턴:

| 세대 | 항렬자 | 위치 | 추정 시기 |
|-----|--------|------|----------|
| 27世 | 老 | 앞글자 | ~1900년대 |
| 28世 | (?) | 뒷글자 | ~1930년대 |
| 29世 | 宇 | 앞글자 | ~1960년대 |
| 30世 | 度 | 뒷글자 | ~1980년대 (빈도 1위) |
| 31世 | 世/東 | 앞글자 | ~1990년대 |
| 32世 | 舒/衍 | 뒷글자 | ~2000년대 |
| 33世 | 浩/珉 | 앞글자 | ~현재 |

**확정 절차**:
1. 마이그레이션 후 자체 빈도 분석으로 1차 추출
2. `hangryeolja_table.confidence` 점수 부여
3. 위원회에 검수 요청
4. `is_verified = TRUE`로 확정

### 자동 추천 로직

```typescript
function suggestHanjaName(
  parentGeneration: number,
  childKoreanName: string  // "성도"
): NameSuggestion {
  const childGen = parentGeneration + 1;
  const hangryeol = lookupHangryeolja(childGen);
  
  if (!hangryeol) return { auto: false };
  
  const [char1, char2] = childKoreanName.split('');
  
  if (hangryeol.position === 'first') {
    // 앞글자가 항렬자
    return {
      auto: true,
      hanja_first: hangryeol.character_hanja,  // 자동 확정
      hanja_second_candidates: lookupHanjaByKo(char2)  // 후보 표시
    };
  } else {
    // 뒷글자가 항렬자
    return {
      auto: true,
      hanja_first_candidates: lookupHanjaByKo(char1),
      hanja_second: hangryeol.character_hanja
    };
  }
}
```

### 한자 후보 빈도 정렬

기존 DB의 동일 한글 이름의 한자 빈도순 정렬:

```sql
SELECT 
  SPLIT_PART(name_hanja, '', position_index) AS hanja_char,
  COUNT(*) AS frequency
FROM persons
WHERE name_ko LIKE '%' || target_korean_char || '%'
GROUP BY hanja_char
ORDER BY frequency DESC;
```

### 딸 이름의 예외

**중요**: 딸 이름은 항렬자 규칙 적용 외부 (전통). 시대별 유행:

```
1940년대~: "○子" (順子, 貞子) — 일본 영향
1960~80년대: "○淑", "○順" 가장 흔함
1990년대~: 한글 이름 (슬기, 여운)
2000년대~: 짧은 외자 한자 (賢, 淑)
```

→ **딸 이름은 항렬자 자동 추천 비활성화**, 자유 입력.

## 4. 세대(世)와 분파(派)

### 세대 구조

행주기씨는 **시조 1세부터 33세**까지 33대에 걸쳐 있음.

```
1세 (시조): 1명
2~10세: 154명 (고대, 자료 부족)
11~20세: 3,066명 (고려~조선중기)
21~30세: 31,002명 (조선후기~근대) ← 절대다수
31~33세: 952명 (현대) ← 위기 영역
```

세대는 `persons.generation` 컬럼에 정수로 저장.

### 분파 트리 구조 (3단계)

```
1단계 — 대분파 (시조 직속, 6개)
  └── 2단계 — 중분파 (정무공 산하 7개 등)
        └── 3단계 — 세분파 (다수)
```

PostgreSQL `ltree` 사용:
```
'정무공'                              -- 1단계
'정무공.광주'                         -- 2단계
'정무공.광주.승지공.기은문중'        -- 3단계
```

### 분파 권한

```
종친 본인 분파:
- 종친 명단 조회 가능
- 휴대폰 번호 조회 가능 (개인정보 동의 필요)
- 분파 게시판 글쓰기

타 분파:
- 인물 정보 조회 가능 (공개 필드만)
- 휴대폰 번호 비공개
- 분파 게시판 읽기만
```

## 5. 이름 표기 (한글 + 한자)

### 다중 표기 시스템

한 인물이 가질 수 있는 이름:

```
- 이름 (本名): 한글 + 한자
- 자(字): 성년 후 부르는 이름 (한글 + 한자)
- 호(號): 별호, 아호
- 시호(諡號): 사후 임금이 내림
- 군호(君號): 왕족·공신에게 내림
- 왕호(王號): 왕에게만
```

### 데이터 모델

```sql
-- persons 테이블의 이름 컬럼
name_ko         -- 본명 한글 (기성도)
name_hanja      -- 본명 한자 (奇成度)
ja_ko           -- 자(字) 한글
ja_hanja        -- 자(字) 한자 (예: 成道)
ho              -- 호 한글
ho_hanja        -- 호 한자
siho            -- 시호 한글
siho_hanja      -- 시호 한자
```

### 한자 인코딩 주의사항

**EUC-KR (옛 호스팅)**:
- 한자 약 4,888자만 지원
- 일반 인명은 OK
- 자(字)·호(號)·시호(諡號)의 희귀 한자 손실 가능

**UTF-8 (신규 시스템)**:
- 유니코드 CJK 통합 한자 (2만+자)
- 확장 한자 (Ext B~F) 일부는 폰트 필요

**폰트**: Noto Sans CJK 또는 본명조 (확장 한자 지원)

### 검색 통합

```sql
-- search_text tsvector에 모두 포함
to_tsvector('simple',
  COALESCE(name_ko, '') || ' ' ||
  COALESCE(name_hanja, '') || ' ' ||
  COALESCE(ja_ko, '') || ' ' ||
  COALESCE(ja_hanja, '') || ' ' ||
  COALESCE(ho, '') || ' ' ||
  COALESCE(ho_hanja, '') || ' ' ||
  COALESCE(gyeongryeok, '')
)
```

## 6. 음력·양력·간지

### 행주기씨 족보의 표기 방식

```
1962壬寅6월12일 ~
└─ 양력 연도(1962) + 간지(壬寅) + 음력 6월 12일
```

### 변환 규칙

- **양력 연도**: 그대로 저장
- **간지(干支)**: 60갑자 순환 → 자동 계산 가능
- **음력 월일**: 별도 컬럼 + 양력 변환 결과도 함께 저장

```sql
persons (
  birth_date_western DATE,        -- 양력 변환 결과 (1962-07-13 등)
  birth_year INTEGER,             -- 1962
  birth_lunar_month INTEGER,      -- 6
  birth_lunar_day INTEGER,        -- 12
  birth_ganji VARCHAR(8),         -- 壬寅
  birth_is_lunar BOOLEAN          -- TRUE
)
```

### 60갑자 자동 계산

```typescript
const HEAVENLY_STEMS = ['갑(甲)', '을(乙)', '병(丙)', '정(丁)', '무(戊)',
                         '기(己)', '경(庚)', '신(辛)', '임(壬)', '계(癸)'];
const EARTHLY_BRANCHES = ['자(子)', '축(丑)', '인(寅)', '묘(卯)', '진(辰)',
                           '사(巳)', '오(午)', '미(未)', '신(申)', '유(酉)',
                           '술(戌)', '해(亥)'];

function getGanji(year: number): string {
  const stemIdx = (year - 4) % 10;
  const branchIdx = (year - 4) % 12;
  return HEAVENLY_STEMS[stemIdx][2] + EARTHLY_BRANCHES[branchIdx][2];
}

getGanji(1962);  // "壬寅" ✓
```

## 7. 묘소(墓所) 정보

### 전통 표기

```
좌향(坐向): 申坐艮向 등 (한자로 방향 표시)
비문(碑文): 묘비에 새긴 글
행장(行狀): 생전 업적 요약
```

### 데이터 모델 (Phase 1.5에서 PostGIS 활용)

```sql
persons (
  tomb_address VARCHAR,                    -- "경기도 ○○군 ○○리"
  tomb_location GEOMETRY(POINT, 4326),     -- PostGIS 좌표
  tomb_direction VARCHAR,                  -- 좌향
  tomb_description TEXT                    -- 비문, 행장
)
```

### 활용 (성묘 시즌)

```sql
-- 사용자 위치에서 50km 이내 선조 묘소
SELECT name_ko, tomb_address,
       ST_Distance(tomb_location, ST_Point($lng, $lat)::geography) AS distance
FROM persons
WHERE death_year IS NOT NULL  -- 사망자만
  AND ST_DWithin(tomb_location, ST_Point($lng, $lat)::geography, 50000)
ORDER BY distance;
```

추석·한식·기일에 푸시 알림 가능.

## 8. 수단(收單) 워크플로우

### 정의

**수단**: 족보에 새로 등록하기 위한 신청 (개인 정보 제출)

### 용어

```
수단(收單)         — 신규 등록 신청
수단표             — 신청서 양식 (엑셀)
수단비             — 등록 수수료 (1인당 ○○원)
수단금 접수 통장   — 농협 351-0833-9286-23
가승보(家乘譜)     — 본인 직계 가지의 족보책 (10부 이상, 권당 30,000원)
```

### 정합성 정책 (위원회 합의)

```
✓ 신규 등록자만 수정 가능
✓ 2004년 9차 대동보 기록은:
  - 생존자(生者): 근거 자료 제시 시 수정 가능
  - 사망자(亡者): 원칙적 수정 불가
  - 예외: 역사적 고증 시 위원회 심의 → 이사회 의결
✓ 타인과 관계 변경 시: 인우보증(隣友保證) 등 증거자료 필수
```

### 시스템 구현

```
신청 → 입금 코드 생성 → 종친 송금 → 자동 매칭 → 위원회 검토 → 승인 → DB 반영
```

상세는 `FEATURES.md` 참조.

## 9. 외부 표기 — 며느리(子婦) / 사위(壻)

### 며느리 표기

행주기씨 남자의 부인은 **본관(○씨)**으로 표시:

```
"이씨 처(李氏 妻)" — 53명
"○○○ 김씨" — 김씨 본관 표기
```

### 사위 표기

행주기씨 여자의 남편은 **남편의 성명**으로 표시:

```
"차성도 처(車聖度 妻)" — 차씨에게 시집간 딸
```

### DB 모델

```sql
-- 행주기씨 인물의 배우자 (며느리든 사위든)
spouses (
  person_id BIGINT,                  -- 행주기씨 본인
  spouse_name_ko VARCHAR,
  spouse_name_hanja VARCHAR,
  spouse_clan_id BIGINT,             -- 배우자 본관
  ...
)

-- 통계용 별도 캐시
clans (
  daughter_in_law_count INTEGER,     -- 며느리 받은 수
  son_in_law_count INTEGER           -- 사위 보낸 수
)
```

### 검색 시 자동 변환

`name_ko = "차성도 처"` 형태로 저장된 경우, child_label에 "딸"로 표시.

## 10. 청년 친화 메시지 (Phase 2 전용)

### 도메인 의식

청년 종친에게는 **단순 정보 제공이 아닌 정체성 부여**가 핵심.

```
약함: "당신은 행주기씨입니다"
강함: "당신은 청백리에 녹선된 영의정 ○○공의 9대손입니다"
```

### 콘텐츠 톤

- 다크 모드 카드 (인스타·SNS 공유 적합)
- 강력한 정체성 메시지
- 게임 메커닉 (등급, 배지, 컬렉션)
- 친구 초대 → 바이럴 추적

## 참고: 표준 GEDCOM과의 차이

서양 족보 표준 GEDCOM이 한국 족보를 수용하지 못하는 이유:

| 항목 | GEDCOM | 한국 족보 |
|------|--------|----------|
| 양자 표현 | 단순 NOTE | 출계/입후 정식 관계 |
| 세(世) | 없음 | 시조 기준 세대 번호 |
| 분파(派) | 없음 | 트리 계층 |
| 항렬자 | 없음 | 의무 명명 규칙 |
| 자/호/시호 | 없음 | 별도 1급 필드 |
| 음력/간지 | 없음 | 표준 표기 |
| 묘소 좌향 | 없음 | 한자 방위 표기 |

→ **자체 데이터 모델 필수**, GEDCOM은 export 옵션으로만 지원.
